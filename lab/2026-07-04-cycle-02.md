## What evidence was gathered?

### Scan B — Behavioral (70+ invariants)

The CCI pipeline produces exactly the same event sequence (`init → step×N → terminate`) regardless of algebra type. All four test suites confirm:

- Runtime calls exactly four lifecycle hooks (`runtime.py:57,68,69,86`)
- Trace is immutable after construction (defensive copy on `.events`)
- Hash chain is always unbroken
- All interpreters produce `is_nan` in result envelopes
- All step evaluators produce `{step_id, expected, actual, match}`

Five structural weaknesses documented:
1. No `process=None` guard
2. No `inputs=None` guard (crashes in all executors)
3. `finished()` returning non-bool can cause infinite loop
4. `result()` exception loses the trace
5. Event payload mutation via shared references

### Scan C — Information Flow (2 structural disconnects)

Traced knowledge from `inputs → initialize → step → trace → interpreter → output`.

Key finding: the reconstructor checks for `matched_condition` at `event.payload` top level (`reconstructor.py:125`), but the runtime always nests it under `event.payload["transition"]`. Branch detection is structurally disconnected — the reconstructor's branch list will always be empty.

Also: `_safe_state` strips `_`-prefixed keys before hashing, meaning internal implementation state is invisible to causality tracking.

### Scan D — Temporal (2 properties confirmed, 1 limitation)

`self` is never referenced in `CognitiveRuntime.execute()` (lines 36-98) — the runtime is stateless by structure, not just convention.

Causal edges are order-independent (hash matching), but temporal edges are position-dependent. `structurally_equivalent` uses positional `zip(strict=True)` — not a true isomorphism test.

### Scan E — Ownership (convention-only enforcement)

Only `CognitiveCommit` uses `@dataclass(frozen=True)`. Everything else is convention:
- `CognitiveEvent` has `__slots__` but writable attributes
- Process/executor state is a plain dict
- `ReconstructedGraph` is mutable

Interpreters are provably stateless (10/11 have no `__init__`).

### Scan F — Failure (3 critical trace-loss paths)

Only 3 exception handlers in ~1,550 lines of CCI code. Three lifecycle hooks can fail and lose the trace:
- `initialize()` raises: no events recorded
- `step()` raises: init recorded but all steps lost
- `result()` raises: all steps recorded but trace never returned

Interpreters are always graceful — all use `.get()` with type-appropriate defaults.

## What surprised us?

1. **Reconstructor branch detection is completely disconnected** from the runtime payload schema. This was not hypothesized in Cycle 1. The reconstructor would never detect a branch with current recording.

2. **The runtime is structurally stateless** — `self` is never used in `execute()`. This is stronger than the "process is stateless" invariant from Cycle 1. The runtime itself could be a module-level function.

3. **Only one protocol invariant is enforced at runtime**: `step_result["next_state"]` at `runtime.py:71`. Everything else — `transition`, result shape, state skeleton, termination predicate — is conventional. The architecture is remarkably minimal.

4. **3 of 4 lifecycle hooks can fail silently**. `_state_hash` is the only guarded operation. This means the most robust part of the runtime is the hashing, not the execution.
